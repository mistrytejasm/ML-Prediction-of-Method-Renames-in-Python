## Master dataset and training configurations

The 46-feature master dataset is **unchanged** and remains the canonical, audited source dataset. The approved training configurations select columns from it; they are experimental settings, not changes to the master:

| Configuration | Features | Definition |
|---|---|---|
| Main experiment | **40** | 46 minus `call_sites`, `rel_call_sites`, `class_depth`, `is_async`, `file_loc`, `file_n_methods` |
| Comparison experiment | **42** | Main + `file_loc`, `file_n_methods` |

| Not used in either experiment | Reason |
|---|---|
| `call_sites` | Excluded: its search scope is every Before file the future commit changed, so it depends on the commit's changed-file list (`docs/temporal_leakage_audit.md`) |
| `rel_call_sites` | Excluded: built from `call_sites`, so it inherits the same dependence |
| `class_depth` | Dropped: near-duplicate of `in_class` (99.8718% equal; Pearson r = 0.996514) |
| `is_async` | Dropped: near-constant (37 methods, none renamed) |

The other eight `rel_*` features passed the Before-only recomputation audit: 33,232 values recomputed from the Before file alone, 0 mismatches.

**Research scope and data conditions**

- The scope is methods belonging to files edited by the future commit (ActRef stores only changed files).
- About 9.5% of eligible methods (3,263) have an unknown outcome (deleted, moved, or renamed undetected) and are excluded.
- A file supplies rows only if both its Before and After versions parse.

**Future work (not implemented, not approved):** an own-file-only call count as a replacement for `call_sites`, counting calls only inside the method's own Before file. It is not in the master dataset or the feature code.
