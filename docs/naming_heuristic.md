# Naming heuristic (Stage 7): definition, research status and audit

`naming_heuristic` (`NamingHeuristicClassifier`, `src/models/baselines.py`) is an
**exploratory, post-hoc, rule-based naming heuristic**. It is not a preregistered or
independent confirmatory baseline. The chance-reference baselines are
`dummy_prior` and `stratified_random`.

## Research status

The six flags were proposed after label-derived feature summaries, computed on all
31,209 rows (held-out test rows included), had been seen (audit below). Selecting the
flags was therefore not fully blind to the data. To limit the influence of those
summaries:

- every approved Before-only name feature that encodes a common naming guideline was
  taken as one flag, whichever direction its summary seemed to point;
- all flags have equal weight;
- no flag, weight or threshold was chosen or tuned using labels.

Results for this heuristic are reported as exploratory.

## Definition

Score = share of the six flags raised (0, 1/6, ..., 1). No training.

| Flag | Condition | What the feature measures | Kind |
|---|---|---|---|
| `short_token` | `name_short_tokens > 0` | a word of 1-2 letters that is not a digit run and not in `SHORT_OK` = {id, io, ip, ok, db, os, ui, x, y, z, fn, nn, lr}. Also counts English words such as is, to, on, of, in, by, at (`is_valid`, `to_dict`, `on_click`) | naming defect (abbreviation / brevity) |
| `vowelless_token` | `name_no_vowel_tokens > 0` | a word of 2+ letters with no a/e/i/o/u and not a digit run (`cnt`, `nb`; also `db`, `fn`, `lr`, `nn`, `tf`) | naming defect (abbreviation) |
| `single_character_name` | `name_single_char == 1` | the name without leading/trailing `_` is one letter | naming defect (brevity) |
| `contains_digit` | `name_has_digit == 1` | any digit in the name (`run2`, but also `md5`, `utf8`, `v2`) | naming convention, often legitimate |
| `first_word_not_in_verb_list` | `name_starts_verb == 0` | the first word is not in `VERBS` (68 words in `src/features/method_features.py`, including to, from, is, has). Verbs missing from the list (visit, draw, emit) also raise it | naming convention (verb-phrase method names); properties, factories and callbacks are often nouns |
| `camel_case_in_snake_file` | `style_mismatch == 1` | camelCase name in a file whose methods are mostly snake_case/lower | contextual style inconsistency: the same name is fine in a camelCase file, so this describes the name in its file, not the name itself |

**Fixed word lists:** `VERBS` (68 words) and `SHORT_OK` (13 tokens) in
`src/features/method_features.py`, and the vowel set a/e/i/o/u (y is not a vowel).

**Excluded: `name_is_private`.** A leading underscore marks visibility (an API
decision), not a naming defect. `split_name()` strips it before the other flags are
computed.

**Operating points.**
- `predict_proba()` gives the continuous score. The controlled evaluation applies the
  Stage 6 maximum-F1 threshold, chosen on development OOF scores, exactly as for
  every other model.
- `predict()` is a separate, fixed convenience rule: at least 3 of 6 flags
  (`DEFAULT_RULE_MIN_FLAGS`). It never replaces the threshold selection.

## Overlap: the flags are not six independent defects

Checked with the real `name_features()` on example names (no dataset rows used).

| Example | Flags raised | Why |
|---|---|---|
| `f` | single_character_name, short_token, first_word_not_in_verb_list (3/6) | one letter: no listed verb has one letter, and `f` is not in SHORT_OK |
| `x` | single_character_name, first_word_not_in_verb_list (2/6) | `x` is in SHORT_OK |
| `nb`, `tf_idf` | short_token, vowelless_token, first_word_not_in_verb_list (3/6) | one two-letter vowelless word raises two flags |
| `md5_hash` | short_token, vowelless_token, contains_digit, first_word_not_in_verb_list (4/6) | `md5` splits into `md` + `5` |
| `is_valid`, `to_dict` | short_token only (1/6) | `is`/`to` are listed verbs but are also short tokens |
| `visit_node`, `size` | first_word_not_in_verb_list (1/6) | the list is incomplete; nouns are common for properties |

- Brevity/abbreviation (short_token, vowelless_token, single_character_name) can carry
  up to 3/6 of the score, so equal weights per flag are not equal weights per concept.
- `camel_case_in_snake_file` can fire only for camelCase names.
- Scores take only 7 values, so many methods tie.
- Renames that only change visibility or meaning are invisible to the heuristic.

## Audit of label-derived statistics in `docs/data_dictionary.md`

The dictionary is generated by `src/data/generate_dataset_report.py` from the master
dataset (all 31,209 rows). Only the items below use the target `renamed`. No split
existed when they were generated, so none separates development from test.

| Item | Meaning | Kind | Data | Influenced the six flags? |
|---|---|---|---|---|
| `mean_renamed`, `mean_not_renamed` columns of "Feature value ranges and class means" (46 rows) | mean of each feature among renamed / not-renamed rows (`X[y == 1].mean()`, `X[y == 0].mean()`) | label-derived class comparison | complete dataset, test rows included | **Possibly.** The values for the name features (and, incidentally, `cyclomatic`, `rel_loc`, `rel_name_body_overlap`) were seen before the flags were proposed. Without knowing which column was which, the flags were not selected or weighted by them, but influence cannot be ruled out. |
| `name_is_private` note: "Visibility-only renames (43 positives) toggle exactly this flag" | count of positives whose rename only changed the leading underscore | label-derived count | complete dataset | **Possibly**, for excluding `name_is_private`. The stated reason (visibility, not a defect) is conceptual, but the note was visible. |
| `is_async` notes: "37 methods, none renamed" / "0 renamed" | positives among async methods | label-derived count | complete dataset | No (`is_async` is not a name feature and is dropped) |
| "3,263 methods with unknown outcome are excluded" | rows dropped because their label could not be determined | dataset-construction count (uses the After code, not `renamed`) | all commits | No |
| `min`, `median`, `p99`, `max`, `unique` columns | value ranges of each feature | descriptive, label-free | complete dataset | No |
| `class_depth` / `in_class` near-duplicate statistics | equality and correlation between two features | descriptive, label-free | complete dataset | No |

The generator also writes class medians (`median_renamed`, `median_not_renamed`) for
`file_loc` and `file_n_methods` into `docs/data_quality_report.md`; neither is a name
feature. The Phase 1 preprocessing audit (`reports/audit/preprocessing/positive_vs_negative.csv`)
contains full-dataset class comparisons (Cliff's delta, Hedges' g) for every feature.
It was produced earlier in this project by the same assistant that proposed the
flags, so exposure to it cannot be ruled out either. It was not consulted when
designing or revising the heuristic.

**Documentation defect found and corrected:** the dictionary said `name_starts_verb`
uses "a fixed list of 72 verbs"; `VERBS` has 68 unique entries (68 literals, no
duplicates). The "72" was typed by hand in `src/data/generate_dataset_report.py`. The
generator now prints `len(VERBS)`, and the regenerated `docs/data_dictionary.md` /
`.csv` say 68 (approved correction; no other generated output changed).
